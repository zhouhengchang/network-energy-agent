# 试验网验证计划（Validation Plan）

- **项目名称**：基于 LangGraph 的小区扇区自主休眠节能调度 Agent
- **验证环境**：紫金山实验室 Pre6G 试验网（小区级无线接入域）
- **文档版本**：v1.0
- **编制日期**：2026-10-21

---

## 1. 验证目标

本验证计划要回答三个问题，且每个问题都有**可量化、可复算**的答案：

| 编号 | 验证问题 | 判定标准 |
|---|---|---|
| V1 | Agent 智能休眠相比"扇区常开"，能降低多少能耗？ | 7 天日均能耗降幅 ≥ 8% |
| V2 | 节能是否以牺牲用户体验为代价？ | 用户服务中断比例 ≤ 1% |
| V3 | 决策过程是否可审计、可回滚？ | 每周期决策均可复算，突发流量 100% 触发回滚 |

---

## 2. 试验场景与数据要求

### 2.1 场景定义

| 项 | 配置 |
|---|---|
| 站点类型 | 单小区、多扇区（推荐 3~6 扇区，与 MVP 的 6 扇区对齐） |
| 覆盖场景 | 优先选择**夜间话务明显回落**的区域（办公区/园区/商业区混合），节能空间最大 |
| 连续时长 | 7 × 24 小时连续运行 |
| 数据粒度 | 15 分钟（与决策周期一致） |
| 决策周期 | 15 分钟一次自主调度（96 次/天，672 次/7 天） |

### 2.2 需要的只读数据字段

| 字段 | 类型 | 说明 | 用途 |
|---|---|---|---|
| `timestamp` | 时间 | 15 min 对齐 | 时间轴 |
| `sector_id` | 字符串 | 扇区唯一标识 | 实体标识 |
| `prb_usage_pct` | 0~100 | 上行/下行 PRB 平均利用率 | 负载特征 |
| `active_users` | 整数 | 扇区在线用户数（RRC 连接态） | 迁移用户量估算 |
| `cell_availability` | 布尔 | 小区/扇区当前是否可用 | 状态基线 |

**明确不需要的字段**（降低数据合规风险）：
- ❌ 任何用户标识（IMSI / SUPI / GUTI / 手机号 / MAC）
- ❌ 任何信令内容、任何用户面报文
- ❌ 任何精确位置信息（经纬度、TA 级定位）

即：**只申请"聚合到扇区级别的统计量"**，从根源上不涉及个人信息。

### 2.3 数据安全约束

1. 所有数据仅在试验网内网环境流转，不上传公网；
2. 落盘数据仅保留聚合指标，不含原始信令；
3. 数据保留期不超过试验周期 + 30 天，到期删除；
4. 项目代码与文档中不出现任何真实网络标识（小区 ID 做脱敏映射）。

## 3. 对照试验设计

### 3.1 两组对照

| 组别 | 策略 | 说明 | 角色 |
|---|---|---|---|
| **A 组（对照组）** | 基线：扇区常开 | 所有扇区 7×24 小时不休眠 | 能耗上界、QoS 最优参考 |
| **B 组（试验组）** | Agent 智能休眠 | 每 15 min 由 Agent 决策休眠组合 | 待验证策略 |

> 补充参照（非必需）：可增加 **C 组 = 随机休眠**，用于说明"节能效果好不等于调度智能"。在 MVP 阶段 C 组已完成仿真，可作为对照。

### 3.2 公平性控制（重要）

为避免两组结果不可比，必须严格控制以下变量：

| 控制项 | 要求 |
|---|---|
| 时间对齐 | A/B 两组使用**同一时间段**的同一份话务数据（离线回放）或**同一小区同时段**的分组对比 |
| 流量同源 | 两组输入完全一致，禁止 B 组使用"更有利"的数据 |
| 参数一致 | 功耗模型参数、QoS 模型参数完全相同 |
| 环境一致 | 同一周内完成，避开节假日与特殊事件 |

**推荐方式**：**离线回放**（用 A 组实采的 7 天只读 KPI 作为输入，分别回放 A/B 策略）。这种方式不改变现网任何配置，完全无风险，且两组输入严格同源。

### 3.3 试验流程（7 天）

```
D-1  接口联调：只读 KPI 拉通，确认 15 min 数据完整率 ≥ 99%
D1   冷启动：Agent 只记录不"执行"，人工核对 96 条决策合理性
D2-D6 连续运行：每组策略按 15 min 周期决策，日志全量留存
D7   收尾 + 数据导出 + 异常复盘
D+7  出具验证报告
```

## 4. 验证指标

### 4.1 一级指标（验收口径）

| 指标 | 计算公式 | 目标值 |
|---|---|---|
| **日均能耗降幅** | `(E_A − E_B) / E_A × 100%` | ≥ 8% |
| **用户服务中断比例** | `Σ未服务用户 / Σ在线用户 × 100%`（按 15 min 聚合加权） | ≤ 1% |

### 4.2 二级指标（过程观测）

| 指标 | 说明 | 期望 |
|---|---|---|
| 休眠扇区·周期数 | `Σ 每周期休眠扇区数` | 集中在 00:00–06:00 |
| 日均休眠时长 | 每扇区日均休眠小时数 | 1.5 ~ 3 h |
| QoS 越界拒绝次数 | 因超阈值而放弃休眠的周期数 | 少量且集中在忙时 |
| 突发回滚次数 | 触发 `rollback` 的周期数 | 与真实话务突发事件数吻合 |
| 决策耗时 P95 | 单周期决策耗时（不含 LLM） | < 100 ms |
| 数据完整率 | 有效周期数 / 应到周期数 | ≥ 99% |

### 4.3 指标计算口径说明

**能耗**：按 §技术方案 §2.1 的功耗模型，用每周期实测的 PRB 利用率折算瞬时功率，再按 0.25 h 积分。若试验网可提供**分扇区实测功耗**（推荐），则直接采用实测值，模型仅作交叉校验。

**未服务用户**：优先采用试验网侧的真实指标（如 RRC 建立失败率、切换失败率折算）；若不可得，则用本项目的 QoS 模型估算，并在报告中**明确标注为估算值**。

> 这一区分写进报告是硬要求：不能把模型估算当成实测结果对外呈现。

## 5. 试验网资源申请清单

### 5.1 申请项

| 序号 | 资源 | 规格 | 用途 | 权限 |
|---|---|---|---|---|
| R1 | 小区扇区负载只读接口 | 15 min 粒度，3~6 扇区，7 天 | 决策输入 | **只读** |
| R2 | 扇区状态只读接口 | 扇区开关状态、可休眠标识 | 状态校验 | **只读** |
| R3 | 模拟决策日志上传接口 | 单向写入，JSON，≤ 1 KB/条 | 决策归档 | **仅日志落地** |
| R4 | 开发机 / 容器资源 | 2 vCPU / 4 GB / 50 GB，内网 | 运行 Agent | 计算资源 |
| R5 | 本地 Ollama 运行时 | CPU 推理，≤ 1B 模型 | 决策解释 | 无外部访问 |

### 5.2 明确不申请的权限（安全边界）

| 不申请项 | 说明 |
|---|---|
| ❌ 基站配置下发权限 | 不修改任何网元参数 |
| ❌ 扇区关断 / 小区闭塞执行权限 | 休眠指令**只记录、不下发** |
| ❌ 网元管理面登录通道（SSH/SNMP Set/NETCONF 写） | 无任何写通道 |
| ❌ 用户级数据访问权限 | 仅用扇区级聚合统计量 |
| ❌ 现网用户面数据 | 不接触任何业务报文 |

### 5.3 资源使用承诺

1. 只读接口调用频率不高于 15 min/次，不产生额外信令压力；
2. 日志上传为单向、小报文，单日数据量 < 2 MB；
3. 试验结束后 30 天内清理全部落盘数据；
4. 不将试验数据用于本项目之外的任何用途。

## 7. 风险与应对

| 风险 | 概率 | 影响 | 应对措施 |
|---|---|---|---|
| 夜间话务回落不明显，节能空间小 | 中 | 降幅达不到 8% | 选点阶段先做 7 天话务画像，优先选夜间负载 < 20% 的小区 |
| 只读接口数据缺失/抖动 | 中 | 决策输入不完整 | 缺失周期直接跳过并保持全开（保守策略，不影响安全） |
| 邻区吸收能力被高估 | 中 | 实际未服务率高于估算 | 用真实掉线率反向校准 `HOLE_RATE`，保守取值 |
| 试验周期内出现节假日/突发 | 低 | 数据不可比 | 剔除异常日，并在报告中说明剔除依据 |
| 审核方对"AI 决策"的顾虑 | 中 | 审批受阻 | 强调"确定性算法 + LLM 仅解释"的双层设计，提供逐条复算样例 |

## 8. 与 MVP 仿真结果的衔接

MVP 阶段已在本地 CPU 完成 24 小时全量回放（合成数据），形成了三组对照（全开 / 随机休眠 / Agent 智能休眠）的完整数据，见仓库 `sim/result/` 目录。

**MVP 结论的作用**：证明**决策链路正确性与代码可运行性**，而非证明真实网络中的节能幅度。
**试验网阶段的作用**：用真实只读 KPI 替换合成数据，验证**节能幅度与 QoS 影响的真实量级**。

两者是"逻辑验证 → 量级验证"的递进关系，MVP 的绝对数值不可直接外推为现网收益，报告中会明确区分。
